# Assignment 4, Part 1 — Market Workstation

**Completed work.** A localhost Vue, FastAPI and SQLite workstation receives Yahoo Finance streaming observations, persists them, and displays candlestick and observed-volume panes through browser WebSockets. The student-designed terminal layout is retained. Part 1 prompt alignment adds CSV practice data, 1m/5m/15m/hourly/daily views, exchange-session handling, candle inspection, UTC date-range replay, explicit replay source/receipt timing, and Yahoo disconnect/reconnect controls. Symbols: AAPL, MSFT, SPY and BTC-USD.

**Key design decisions.** Candles have exactly the six CSV fields; completion, coverage and volume-known metadata remain separate. Different quotes sharing a timestamp are retained unless an explicit correction link establishes replacement. Exact payload repeats are ignored. Missing baselines/totals, resets and multi-minute gaps produce unknown volume, not zero. Exchange calendars align US stock bars to regular sessions, including DST, holidays and early closes; BTC uses UTC days. Replay uses original arrival cutoffs, preserves available revisions, displays the actual arrival being replayed, and never changes stored records. The same aggregation serves history and live/replay views. See the [design pipeline and SQLite schema](https://github.com/kuanenlee0925-blip/market-workstation/blob/main/docs/design-pipeline.md).

**Remaining limitations.** Quotes and volume are sampled approximations, not exchange-certified OHLCV. Calendar coverage is 2000–2035; regular-session stock charts exclude out-of-session quotes while retaining their raw records. A full count of observed minutes does not guarantee a complete trade tape. Identical source payloads cannot distinguish retransmissions from otherwise indistinguishable events. Derived calculations still read unbounded per-symbol history, so long-running scale is unverified. The yfinance adapter uses private transport/decoder attributes and requires upgrade checks.
